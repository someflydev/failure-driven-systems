# Title

Name the exercise as a concrete engineering task.

## Phase

State the curriculum phase and why this work belongs there.

## Concepts

List the concepts the learner should practice.

## Prerequisites

Name the files, tools, domain ideas, and prior exercises the learner should
understand before starting.

## Build/Change Task

Describe the specific behavior, files, or system change the learner must build.

## Constraints

State the boundaries that keep the exercise focused, including technologies or
architecture moves that are deliberately out of scope.

## Failure Modes

Name the mistakes, broken states, or production risks the learner should watch
for while building.

## Expected Reasoning

Describe the judgments the learner should be able to explain after completing
the work.

## Verification

List the commands, manual checks, database checks, or review steps that prove
the work behaves as intended.

## Reflection Questions

Ask questions that make the learner connect implementation details to system
behavior and tradeoffs.

## LLM Usage

Give guidance for using an LLM as a reviewer, interviewer, or debugging partner
without outsourcing the learner's reasoning.

## Path-Specific Extensions

Provide optional extensions for backend, operations, architecture, or interview
practice paths when the exercise naturally supports them.

## Deployment/Debugging Actions If Relevant

List concrete deploy, runtime, logging, database, or troubleshooting actions.
Write `Not relevant for this exercise` when there is no deploy or runtime
debugging component.
