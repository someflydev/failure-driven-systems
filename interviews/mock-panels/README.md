# Mock Panels

Mock panels are longer interview scripts that combine implementation,
debugging, operations, and architecture defense. Use them after completing the
relevant phase work and gathering learner artifacts.

## How To Run A Panel

1. Choose one panel guide.
2. Gather the evidence package requested by the guide.
3. Run 45 to 60 minutes with one interviewer, a peer group, or an LLM.
4. Ask one question at a time.
5. Require the learner to answer before giving critique.
6. Record weak areas, missing evidence, and one follow-up exercise.

The interviewer may use strong-answer traits to evaluate the response, but
should not read them as model answers. The learner should leave with sharper
questions and review tasks, not memorized scripts.

## Available Panels

- `backend-implementation-panel.md`: API, data model, transactions, tests,
  async behavior, and implementation tradeoffs.
- `distributed-systems-debugging-panel.md`: queues, workers, service
  boundaries, timeouts, retries, incidents, and evidence-first debugging.
- `architecture-staff-engineer-panel.md`: ADRs, datastore/runtime/deployment
  decisions, operational cost, rollback, and system evolution.
